# Генерация статической карты сайта

Job `seo.sitemap.generate` и команда `seo/sitemap/generate` вызывают общий
`SitemapGenerator`. Дочерние файлы имеют постоянные адреса, например
`/sitemaps/sitemap-content-2-00001.xml`. Новые публичные поколения `generated-*`
не создаются.

## Подготовка и публикация

Генератор держит локальную файловую блокировку и сначала полностью записывает
все части в `sitemaps/.building`. Незавершённая сборка после падения процесса
удаляется при следующем запуске под той же блокировкой. Опубликованный индекс
никогда не ссылается на эту папку; закройте её от HTTP-доступа на веб-сервере.

После подготовки каждый готовый XML заменяет одноимённый публичный файл через
`rename` на той же файловой системе. Старый файл не обнуляется и не удаляется
перед заменой. Если файловая система не позволяет такую замену, job завершается
с ошибкой. Основной `sitemap.xml` публикуется последним, когда все его части
уже доступны. На файловых системах с атомарным `rename` индекс переключается
одной операцией; исторический резервный путь замены индекса на Windows
не гарантирует непрерывную доступность. Публикация и HTTP-раздача должны
использовать один постоянный каталог.

Атомарность относится к отдельному файлу, а не ко всему набору: робот между
заменами может получить части разных сборок. При сбое индекс остаётся прежним,
но некоторые части уже могут содержать новые полные XML. Для карты сайта это
допустимо; точный снимок всего набора на один момент не гарантируется.

Если число частей уменьшается или группа исчезает, прежние постоянные адреса
отдают пустой `urlset`, а новый индекс их не содержит. Это предотвращает 404
для старого закешированного индекса и не сохраняет устаревшие адреса страниц.
Поисковик может отметить такой старый файл как пустую карту; отсутствие всех
предупреждений Search Console этим механизмом не гарантируется. Число файлов
зависит от максимального исторического числа частей в каждой группе, а не от
числа запусков. Папка сборки удаляется после завершения.

## Кеширование и переход

Индекс и постоянные дочерние XML рекомендуется отдавать с
`Cache-Control: no-cache` (разрешить хранение, требовать проверку актуальности).
Годовое кеширование постоянных адресов задерживает получение обновлений.
Заголовки статических файлов задаются веб-сервером/CDN, PHP-job их не меняет.

Ранее созданные папки `generated-*` генератор не удаляет и не создаёт новые.
Для старых ссылок, включая уже удалённые поколения, настройте на веб-сервере
перенаправление к соответствующему постоянному XML. Это переход к актуальной
карте, а не восстановление точного исторического снимка. Пример для nginx:

```nginx
rewrite "^/sitemaps/generated-[0-9]{14}-[0-9]+-[a-f0-9]{8}/(sitemap-[a-z0-9-]+-[0-9]{5}\.xml)$" /sitemaps/$1 permanent;
```

Сначала опубликуйте постоянные части, затем включите перенаправление и проверьте
проблемные ссылки: конечный ответ должен содержать XML. Для исторических имён,
которых уже нет в текущем наборе, нужна отдельно проверенная обработка пустого
XML; перенаправление на отсутствующий файл не исправляет 404. Не направляйте
такие запросы на HTML/главную. Старые каталоги удаляются отдельным согласованным
действием только после проверки перехода; автоматической массовой очистки нет.

## Отбор страниц

Разделы с явным запретом индексации и отключённые разделы исключаются, как и
сохранённые фильтры таких разделов. Для шаблона `catalog` исключаются пустые
листинги с учётом вложенных разделов, дополнительных привязок и стандартного
режима наличия. Проверка работает в CLI без веб-сессии. Настройка дополнительных
привязок читается из активной темы, либо задаётся через DI свойством
`includeSecondaryTreeProducts`, если проект меняет её значение по умолчанию.
Произвольные запреты индексации из пользовательского HTML или нестандартных
шаблонов эта проверка не анализирует.

Отключённые коллекции и коллекции без активных товаров текущего сайта
исключаются одним подзапросом. Коллекции используют собственные правила
листинга: наличие на складе и тип предложения не являются условиями исключения.

## Проверки

Изолированные тесты используют временные файлы и SQLite в памяти,
не загружают конфигурацию сайта:

```sh
SKEEKS_APP_ROOT=/app php vendor/skeeks/cms-seo/tests/native-sitemap.php
SKEEKS_APP_ROOT=/app php vendor/skeeks/cms-seo/tests/sitemap-selection.php
```

Первый проверяет job, XML, разделение на части, отмену, постоянство ссылок,
уменьшение и рост числа частей, ошибку публикации и восстановление после
незавершённой сборки. Второй выполняет реальные SQL-запросы отбора:
активность, принадлежность сайту, вложенность, дополнительные привязки,
остатки товара и предложений, склады поставщиков, запрет индексации родителя.

После выкладки проверьте HTTP и XML-тип индекса, всех текущих частей и старых
ссылок после следующего запуска. Убедитесь, что нужные страницы остаются в карте,
а пустые исключены. Локальный тест не подтверждает выкладку или обработку Google.
